## Why

The tool currently ships only as a git repo. Publishing to crates.io and shipping prebuilt binaries in GitHub Releases makes it discoverable (`cargo install randanarana`) and installable without a Rust toolchain (`cargo binstall`, direct downloads) — the two things that let real users actually get the tool.

## What Changes

- **crate metadata**: add `repository`, `homepage`, `keywords`, `categories`, and `rust-version` to `Cargo.toml` so the crate is complete for crates.io and docs.rs.
- **crates.io publishing**: set up a release pipeline that bumps the version, generates a `CHANGELOG.md`, and publishes to crates.io when a release is merged — via `release-plz` (its GitHub Action + config).
- **prebuilt binaries**: initialize `cargo-dist` so tag pushes build and attach installer artifacts for the major platforms (Linux/macOS/Windows) to GitHub Releases, with `cargo binstall randanarana` support.
- **docs**: add crates.io/docs.rs badges to the README and document the new install paths (`cargo install randanarana`, `cargo binstall randanarana`, direct binaries).

This is a tooling, CI, and documentation change: the CLI behavior of the tool itself does not change, so this change declares `skip_specs`.

## Capabilities

### New Capabilities
None — no spec-level behavior change (see `skip_specs: true`).

### Modified Capabilities
None.

## Impact

- **Code**: `Cargo.toml` metadata + `[package.metadata.dist]` section (generated by `cargo dist`); no Rust source changes.
- **CI**: new workflows (`.github/workflows/release-plz.yml`, `.github/workflows/release.yml`) generated by the two tools; GitHub secrets `CARGO_REGISTRY_TOKEN` (crates.io) required.
- **Docs**: `README.md` badges and install section.
- **Manual step for the author**: create a crates.io account, `cargo login`, and add the crates.io token as the `CARGO_REGISTRY_TOKEN` secret so CI can publish.
